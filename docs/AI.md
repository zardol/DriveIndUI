# ИИ: прогноз рисков

Шестой раздел `#/ai` использует OpenAI GPT-6.1 Sol через серверный Responses API. Пользователь выбирает горизонт 15, 30 или 60 минут и запускает анализ вручную. Результат содержит приоритетные риски, численные основания, условный прогноз, уверенность и проверяемые действия. Из карточки можно открыть соответствующий участок или сравнение решений.

Модель не обучалась на данных завода. Ей передаются численные наблюдения текущей симуляции и, только для конфигурации организатора, отдельная история тестового кейса за 1–2 октября. API не получает ключ с клиента, CSV, имена пользовательских файлов, ID машин, свободный текст или расписание будущих событий сценария. Поэтому известное движку будущее не выдаётся за ИИ-прогноз.

Локальный расчёт мощности и очередей подписан «без ИИ». Это приближение при неизменной подаче и циклах, без дискретного движения и обратного влияния блокировок. Остановки, уже случившиеся в текущей смене, помечаются как наблюдения. Для повторения исторического отказа предусмотрена низкая уверенность; калиброванной вероятности отказа нет. Двух дней агрегатов и четырёх остановок недостаточно для проверки такой модели.

## Локальный запуск

1. Скопировать `.env.example` в `.env` в корне проекта и установить `OPENAI_API_KEY`. `.env` исключён из Git. Не добавлять ключ в переменные с префиксом `VITE_`.
2. Выполнить `npm run build` и `npm start`, открыть `http://localhost:3001/#/ai`. В режиме разработки — `npm run dev` и `http://localhost:5173/#/ai`.
3. Для локальной браузерной сборки `http://localhost:4173/#/ai` сервер ИИ отдельно должен работать на `http://127.0.0.1:3001`.

Приложение читает `.env` при запуске сервера. Без ключа расчёт мощности доступен, а кнопка OpenAI не выдаёт фиктивный ответ. Ошибки и отказы API показываются отдельно. Сброс смены отменяет запрос и очищает результат; переход между разделами сохраняет готовый анализ. Результат имеет время среза и помечается устаревшим через пять модельных минут или при смене горизонта.

## Публичный сервер

GitHub Pages не исполняет серверный код. Для новых ИИ-анализов нужен отдельный HTTPS-сервер с `apps/server` или полный серверный стенд. `render.yaml` содержит подготовленную конфигурацию; факт наличия файла не означает, что сервер уже развёрнут.

На хостинге задать `OPENAI_API_KEY` и случайный `AI_ACCESS_TOKEN` в **секретных переменных окружения**. Не помещать их в репозиторий или сборку. Указать публичный origin в `AI_ALLOWED_ORIGINS` (для текущего Pages — `https://zardol.github.io`). Для полного серверного сайта также добавить его собственный origin. Удалённые платные запросы без кода доступа запрещены. Адрес сервера и код вводятся в раскрываемом блоке «Подключение»; код остаётся в оперативной памяти вкладки и не сохраняется в localStorage.

Чтобы не вводить адрес на Pages вручную, установить **обычную переменную репозитория** `VITE_AI_API_URL` в HTTPS-origin сервера и повторно запустить `Publish demo`. Это публичный адрес, а не секрет. Ключ и код доступа никогда не передавать через эту переменную. При отсутствии адреса публичный сайт честно показывает, что OpenAI ещё не подключён.

### Расход и ограничения

- Фиксированная модель `gpt-6.1-sol`, `reasoning.effort=low`, `max_output_tokens=3000`, `store=false`, строгая JSON-схема и повторная проверка ответа сервером.
- Лимит — 150 **попыток** API на сохранённый счётчик, `AI_MAX_CALLS` может только уменьшать его. Ошибки и таймауты тоже занимают попытку. Автоматических платных повторов нет.
- Одинаковые входные данные кэшируются на 10 минут; одновременно выполняются не более двух различных анализов. Между новыми запросами одного клиента — минимум 30 секунд.
- При тарифе $2/миллион входных и $10/миллион выходных токенов типичный проверенный анализ стоил около $0.012. Цена зависит от фактической длины запроса/ответа. Ограничены размер входа и число выходных токенов; лимит попыток оставляет запас относительно выделенных $20. Баланс аккаунта и траты других приложений сервис не видит.
- `AI_LEDGER_PATH` должен указывать на **постоянное хранилище**, сохранённое при перезапуске/развёртывании. По умолчанию локально — `.local/ai-usage.json`. Обновления счётчика защищены файловой блокировкой. Повреждённый счётчик или невозможность записи блокируют платный запрос.
- Запускать один экземпляр API и сохранять счётчик при переносе. Бесплатная файловая система Render временная: без постоянного диска лимит не переживёт новое развёртывание. Это нельзя считать общим бессрочным ограничением бюджета. Дополнительно контролировать расходы в OpenAI Platform; не сбрасывать счётчик во время показа.

## Проверки

Тесты проверяют отсутствие утечки будущих событий, оценку очереди и границ смены, неназначенные заказы, авторизацию и CORS, структуру входа/ответа, отсутствие поддельного ответа при ошибке провайдера, кэш, одновременные запросы, ограничение расходов и сохранение счётчика. Боевые запросы не выполняются в CI. Типы, тесты, обе сборки: `npm run check`.

Официальные источники, проверены 6 октября 2026 года: [модель и тариф](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
