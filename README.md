# DriveIndUI – Drive Industrial UI

**DriveIndUI (Drive Industrial UI)** – интерактивный прототип цифрового двойника автомобильного производства для Qostanai Industry Hackathon. Дедлайн рабочей версии – утро **8 октября 2026 года**.

По умолчанию схема и показатели синтетические. Можно загрузить параметры модели и отдельно просмотреть историю из локального CSV. Прототип не подключён к оборудованию АЛЛЮР; загрузка файла не подтверждает его происхождение и не восстанавливает реальные траектории автомобилей.

**Публичная демонстрация:** https://zardol.github.io/DriveIndUI/

Публичная версия запускает тот же симулятор непосредственно в браузере. Сервер и вход в аккаунт не нужны. У каждого посетителя своя смена; обновление страницы начинает новую. Это самостоятельная демонстрация, а не подключение к заводскому оборудованию.

## Публичная и офлайн-версия

```sh
npm ci
npm run build:demo
npm run preview:demo
```

Открыть `http://localhost:4173`. После установки зависимостей эти команды работают без интернета. Сборка находится в `dist/demo`; пути к ресурсам относительные, поэтому её можно разместить и в подпапке сайта. HTTP-запросы к API в этом режиме не выполняются. Серверный режим ниже сохранён для дальнейшего подключения ИИ и реальных источников данных.

В Windows команда `pwsh -NoProfile -File scripts/package-demo.ps1` упаковывает готовую сборку в `.local/releases/DriveIndUI-offline.zip`. Архив включает статические ресурсы и небольшой сервер без npm-зависимостей. Его нужно полностью распаковать на ПК с Node.js 22+ и запустить `start-demo.cmd`, затем открыть `http://localhost:4175`. Устанавливать зависимости и подключаться к интернету не требуется.

Краткий сценарий защиты: [docs/DEMO.md](docs/DEMO.md).

## Запуск

Нужен Node.js 22 или новее; для команды и CI используется Node.js 24. Команды выполняются из корня репозитория.

```sh
npm ci
npm run dev
```

Открыть `http://localhost:5173`. Интерфейс Vite передаёт `/api` на сервер `http://127.0.0.1:3001`.

Готовая сборка без сервера разработки:

```sh
npm run build
npm start
```

Открыть `http://localhost:3001`. По умолчанию сервер слушает `0.0.0.0`; переменные `HOST` и `PORT` меняют адрес и порт. После установки зависимостей сборка и симуляция работают без интернета. Внешние шрифты и CDN не используются.

## Проверки

```sh
npm run check
```

Команда запускает проверку типов, тесты Vitest и сборку. GitHub Actions выполняет те же проверки для Pull Request.

## Возможности прототипа

- Четыре производственных участка с входными буферами: сварка, окраска, сборка и контроль качества. Склад изображает источник комплектующих.
- Три сценария: штатная работа, сбой окрасочной установки и ограничение мощности сборки.
- Пауза, сброс, переключение сценария и ускорение времени в 1, 10 или 60 раз.
- Импорт JSON-конфигурации: циклы, вместимость буферов, подача, длительность и план смены, вероятность брака, скорость ленты. Перед применением показываются параметры; новая смена начинается на паузе.
- Отдельный режим «История производства»: проверка CSV, воспроизведение по записям, график и таблица, годный выпуск, брак, НЗП и простой. История остаётся в памяти вкладки и не отправляется серверу.
- Выпуск, доля годных изделий, незавершённое производство, загрузка оборудования, простои и журнал инцидентов.
- Оценка выпуска по текущему среднему темпу. Она не является прогнозом обученной ИИ-модели.
- SVG-иллюстрации оборудования, кузова на постах, реальные очереди и анимация только работающего оборудования. Пауза и режим reduced motion останавливают анимацию.
- «Фокус смены»: активный инцидент и самая большая входная очередь. Подробности участка открываются по нажатию или с клавиатуры.
- Полноценный 3D-цех на Three.js / React Three Fiber: объёмные роботы, окраска, сборочный подъёмник, контроль и автомобили. Камеру можно вращать, приближать к участку, переключать на вид сверху и разворачивать сцену.
- Каждая машина имеет постоянный ID и проходит весь конвейер: подъезд, обработку, ожидание и выход. Очереди накапливаются на самой линии без обгона; заполненный буфер блокирует предыдущий участок. Можно выбрать машину и следить за ней камерой.
- Состояния, прогресс и очереди в 3D берутся из общего симулятора. Пауза, остановка оборудования, reduced motion и скрытая вкладка останавливают соответствующую анимацию. Экономный режим уменьшает нагрузку; 2D-схема остаётся доступной.
- Загрузка локальной JSON-схемы размещения с проверкой границ и пересечений. Она не меняет производственные показатели. Подготовка к данным от 5 октября: [docs/DATA-INTEGRATION.md](docs/DATA-INTEGRATION.md).
- Сравнение трёх решений от текущего состояния до конца смены: продолжение работы, обслуживание окраски и резерв мощности сборки. Видны выпуск, изменение простоя, остаток в линии и отклонение от плана.
- Настраиваемые длительности обслуживания и подготовки резерва. Расчёты выполняются на независимых копиях состояния; текущая смена не меняется. В браузерной версии расчёт вынесен в Web Worker.

В серверном режиме каждый браузерный сеанс получает отдельную демонстрацию. Состояние хранится в памяти и удаляется через 30 минут без обращений; перезапуск сервера сбрасывает все сессии. Одновременно допускается до 50 сессий. После длительного сна компьютера симуляция не «догоняет» всё прошедшее время: один шаг учитывает не более пяти реальных секунд. В браузерном режиме фоновая вкладка может замедлять таймер; активный показ следует вести в открытой вкладке.

Смена сценария и сброс обнуляют симуляцию, сохраняя конфигурацию, выбранную скорость и состояние воспроизведения. По завершении заданной смены симуляция останавливается; по умолчанию смена длится восемь часов. Обновление страницы публичного стенда возвращает учебную конфигурацию. В серверном режиме конфигурация живёт до удаления сессии.

## Размещение

GitHub Actions публикует браузерную сборку в GitHub Pages после изменения `main` и успешного `npm run check`. Настройки: `.github/workflows/pages.yml`. Публикация не заменяет локальную резервную сборку.

`render.yaml` остаётся альтернативой для размещения полного серверного режима. Он не развёрнут. Подключение OpenAI-помощника к публичной версии потребует отдельного серверного endpoint; API-ключ нельзя помещать в статическую сборку.

Сравнение использует заранее заданные события сценария. Обслуживание гарантированно устраняет дальнейшие отказы окраски, а резерв моделируется удвоением скорости обработки на сборке после переналадки. Это допущения учебной модели, а не подтверждённый эффект на реальном заводе. Стоимость ресурсов и экономическая окупаемость пока не рассчитываются.

Следующие этапы: интеграция данных 5 октября, калибровка модели, объяснение результатов и материалы защиты. ИИ-помощник дополняет проверенные расчёты; его недоступность не должна мешать демонстрации.
